# Study 115 · The RTDB and Bijection interface

Five verbs cover the proposed installed data plane. The complete hosted boundary needs four additional privileged verbs, for **nine** in total. An application transaction cannot install its own authority, create independent recovery custody, select a recovery image, or close the deployment. The [action inventory](inventory.md) lists 115 owned Flight actions, 20 PGWire and session forms, five lifecycle operations and 11 recovery actions. It also maps operations carried inside those requests.

## Data-plane contract

A cut identifies an exact committed history prefix of one installed incarnation. A logical world position can refer to more than one retained source cut. A system-time selector resolves to a cut inside an authorized history, while business-valid time remains a query input. A current read needs a certified admission and a source floor. Those requirements also apply when the implementation can serve the result locally.

| Verb | Inputs and result |
| --- | --- |
| `transact` | One installed authority and principal, a basis, a stable mutation identity, typed guards and a grouped effect. Compare the relevant exact guard evidence at ordered acceptance, apply the chosen branch atomically, and return its original decision, cut and ordered observations. An exact retry retrieves the original outcome while the authoritative receipt is retained. A changed binding is rejected. A transaction may carry a checked erasure effect at the same decision when its guards or companion writes must be atomic. |
| `read` | Latest certified, exact, or as-of basis with source and scope constraints, plus a typed query. Return its exact resolved cut, the query result and any bounded typed validation evidence. All pages and derived projections share the chosen basis. Retry performs fresh admission at the same logical basis. |
| `subscribe` | Scope and exclusive cursor. Emit ordered visible deltas with their exact publication edges through a certified cut, or signal a snapshot restart when the cursor loses coverage. Restart from a newly admitted certified snapshot at or above the returned basis. Retained history queries can page backward or select a bounded interval using `read`. |
| `hold` | Admit an exact or freshly certified cut for a bounded horizon under one owner, or release that exact hold. RTDB keeps the required archive, checkpoint and suffix borrows while admitted work can use them. A held read still checks the applicable erasure and delivery gates. |
| `forget` | An authorized subject binding and erasure identity, with current guard and deadline where required. Order suppression, coordinate RTDB's clean successor and generation rotation, and give original decision and completion evidence. External application key owners contribute to completion for their own custody domains. |

Hold plus a latest read means atomic select-and-pin or read from the cut returned by hold. Picking latest twice makes the data and protection name different cuts. Multi-relation and same-order world decisions are one `transact`. Decomposing them into independent successful writes admits visible partial effects. Comparison evidence must identify the exact publication, typed predicate, result or frontier, and its authority and validity scope. A count can return the same number after a membership change. Use equality of count only for contracts that depend on count alone.

The Lean model proves point and ordered range projection at a fixed cut, historical prefix stability, same-decision point/count validation, refusal invisibility, exact original mutation retry, lease and floor safety, visible ordered watch batches and restart, effective point overlay precedence, and subject suppression with timed prior-cut refusal. The action table marks the corresponding modeled portions as E/L. No E/L row claims Rust or wire refinement.

## Compositions that need more evidence

| Family | Conditions for the composition |
| --- | --- |
| Temporal points, intervals and histories | Resolve the original position and the side of its assertion, then evaluate the same typed predicate on retained versions. Include empty answers and the latest purge/lifetime frontier in the witness. Lean covers simple valid instants, half-open validity, and stable prefixes. Assertion ordinals, valid-region boundaries, lifetime cutoffs, historical version ordering and typed SQL selection remain unproved. |
| Typed ordered, unique, spatial and text reads | At one protected basis, use the same schema/path generation, total sort key, complete typed identity and pagination edge. Rank over the whole effective corpus before taking a page. Preserve spatial predicate and boundary conventions, lifetime/coverage failure, exact total, ties and typed evidence. A stateless cursor can carry these bindings and still consume transport capacity. Native indexing, ranked parity and witness codecs remain unproved. |
| Branch selection and publication | Bind a Root pin and a local overlay cut, interpret tombstones before filling from the parent, and preserve original clock/position coordinates. Pin inputs before a conditional successor registration. Compare every predecessor and proposed binding and install durable successor custody in one `transact`. Refusals release the provisional holds or let their horizons expire. Lean checks one point override including absence. Two independently certified input positions, exact destination readmission, archive lifetime, multi-world publication and retained acquisition races remain unproved. |
| Changes and dependency polling | Retained typed events are queryable through the held through-cut. Merge by exact publication edge before applying a group cap and return a coverage edge even for an empty page. Subscribe for forward progress and read for bounded retained scans or reverse pages. Restart with a snapshot on a live-watch gap. Original table-local sequences, masked event positions, merged coverage and original archived intervals remain unproved. |
| Catalog declarations and checked effects | Represent schema/path declarations in typed transaction plans that the resolver validates and orders with data and receipts. Keep staged evaluation separate from ordered acceptance. Evaluate final-state capacity against the proposed staged effect and commit the original funded outcome at the same decision. Implementation of schema provenance, corpus/index coverage, deadlines, secure cross-scope authorities and stage/final-state checks remains unproved. |
| Erasure and physical expiry | An ordered predicate plus checked forget effect can replace a private erase statement or expiry nomination, provided RTDB honors the original creation, identity, authorized replay floor, completion deadline and exact retirement receipt. Clean root construction, payload-key generation rotation, absence, custody drains and survival across failover remain unproved here. |
| Frozen recovery-stage queries | Use an admin-issued read capability to select the exact source, manifest, destination and stage operation. A layering verdict of accidental concerns the extra boundary operation. The underlying invariants still apply. For example, `OfferFundedMutationClock` creates a real booking and `SwitchPreparedProposal` may depend on a value known before its decision. If a target must be known before external work, record the bounded booking with `transact` and consume it with a second, compare-and-set `transact`. Otherwise choose the acceptance time in one transaction. Similarly, a sealed range predicate may need portable authenticated bytes. Attach them to the admitted read result and validate them at acceptance.

## Privileged controls

| Verb | Owned effect | Boundary counterexample |
| --- | --- | --- |
| `install` | Allocate and certify a deployment incarnation before ordinary admission. | A row write at a missing deployment can mint its own authority. |
| `archive` | Create an independently retained, authenticated checkpoint or exact suffix with its own custody and manifest receipt. | A row transaction can manufacture an archive attestation without creating independent custody. |
| `restore` | Seed or replace a serving or staged recovery basis after verifying source, manifest, destination and applicable predecessor seal. | A data row can become the selected image without recovery evidence. |
| `retire` | Fence new operations on the exact deployment, archive or stage scope, drain admitted effects and obtain original terminal custody evidence. | Subject forgetting can close deployment authority. Closing without a drain can dispose while an admitted reader still owns inputs. |

The distinction is by authority and observable effect. An arbitrary finite composition of the five operations leaves installed identity, independent recovery custody, selected recovery image and the terminal authority fence unchanged. Each of the four privileged operations has a witness that changes its corresponding component, so no data-plane sequence implements it under this contract. Encoding the same privileged effects as a transaction command would retain the four authority operations under a common transport name. The TLC model tests this framing and the dispose/drain order over a bounded transition system. It leaves provider evidence abstract. Status and archive projections reuse `read` with the corresponding admin capability.

Provider owners enforce physical revocation and stable absence. | Fences | **Logkeeper** owns installed write epoch and append fencing. **RTDB** owns resolver, source-floor and resource admission and checks the installed scope. **Bijection** retains business fences such as subject suppression, task fate, source handoff policy and the right to publish a branch. ## Ranked boundary proposal

1. Specify the five verbs against authenticated cuts and exact mutation receipts. Collapse point/range/search/version wire variants into typed reads and effects. Keep Flight, PGWire and the installed admission path as adapters during compatibility work.
2. Make the four privileged controls explicit on the hosted administrative plane. Preserve independent role credentials and capability-shaped evidence. Route only installed incarnations through the portable contract.
3. Move source-proof, prepared-read, hold-handle, seat and witness-grant machinery behind admission. Put user-visible range, causal and clock guarantees in the request and result types. Fold separate validations into the ordered decision where no external work depends on an advance booking.
4. Replace attempt-marker and session-retry conventions once trace comparison covers accepted, refused, lost and expired outcomes, including the original observation clock after handoff. Replace forward change polling with cursor subscriptions plus certified restart. Keep bounded original-history queries and frozen archive replay as explicit use cases.
5. Qualify cryptographic erasure, independent media and seat drain on real providers, then measure end-to-end costs. A reduction in wire actions does not establish fewer syncs or resource admissions.

## Owner decisions

All D01–D06 stand. D01 is represented by fresh same-basis admission and an exact mutation receipt. A live handshake's mint retry may recover transport standing without recovering an earlier read answer. D02 keeps holds and makes old-generation answer custody unreadable at the deadline. The model abstracts cryptographic destruction and completion receipts. D03's protected-write quorum stays a premise. D04 requires cursor restart after retention loss. A caller that needs exact historical events beyond the live horizon needs an explicitly retained archive or a separately approved feed product. D05 confines the proposed portable contract to installed journals. Existing directory recovery call sites are evidence of demanded operations and give no proof of installed equivalents. D06 leaves latency, recovery and maintenance budgets to measurements. This study makes no claim about either Wave R speed hypothesis.

## Reproduction and limits

Run `python3 verification/115-interface/run.py` from the worktree. It uses Lean 4.35 through the pinned `lean-toolchain` and the specified TLC 1.7.4 jar and Java path by default. The paths can be overridden by `LAKE_BIN`, `JAVA_BIN` and `TLC_JAR`. The runner checks the Lean version and jar digest. Full logs are in ignored `.results/`. See [expected results](expected.md) for all controls and witnesses.

Lean covers one ordered store and unbounded list histories in its quantified theorems. Executable fixtures use two subject keys in a single relation, finite valid-time intervals, and a deterministic acceptance fold. Recovery, consensus, replica placement, process loss, index parity, cryptographic custody, byte-level framing, cut certificates and resource clocks are outside its proof. TLC has one deployment, one incarnation, one archive flag, three image states, one outstanding borrow, one business row and a physical custody flag. It checks safety against all interleavings within those bounds, with no fairness or liveness claim.
