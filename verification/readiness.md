# Installed-journal readiness

This matrix covers every S, L, P and Q row in [the Logkeeper requirements ledger](requirements.md) as scoped by [D01–D06](requirements.md#owner-decisions--2026-11-23).
It records evidence for individual obligations and identifies the remaining installed-journal work in each row.
Related RTDB models often describe the directory or legacy path. Under D05, use them as design comparisons and qualify the corresponding installed path separately.
D04 keeps checkpoint-based watch restart after retention. The exact historical feed of [Study 17](17-exact-feed/report.md) is outside this matrix.
D02 separates destroying the old payload key by the deadline from later physical ciphertext disposition. Existing holds keep their authorized lifetime.
D03 forbids single-copy acknowledgement while the loss is unclassified.

| Level | Evidence counted |
| --- | --- |
| MP · Model proof | Lean theorem about the model, with the study report giving the claim and premises. |
| BM · Bounded model | TLC exploration. The study report or RTDB runner gives the configurations, controls and bounds. Eventuality requires the model's fairness and availability assumptions. |
| PR · Production refinement | A reported Verus run against production source or a conformance test that compares a shipped path to a stated obligation. Applies to the named function or fixture slice. |
| AT · Acceptance test | A reported run of the applicable installed acceptance scenario with its intended outcomes and a targeted negative case. The matrix distinguishes a refused input from a mutation of the native guard. |
| None | No qualifying evidence for the requirement in its adopted scope. |

`fixture` identifies runnable production-path test source. `harness` identifies a source-linked proof harness without a qualifying run cited here.
`related` identifies a counterpart model whose scope differs from the required installed decision, and `audit` identifies source/design context.
These labels convey no additional evidence level.
For `PR`, the RTDB [results ledger][results] gives the reported Verus suites and their controls. For grant-fenced promotion, the [co-design plan](codesign.md#workstreams) records the two rejected driver mutations.

The native journal acceptance source exercises lost replies and replacement over authenticated journal sockets. The co-design plan records the prior passing RTDB Multi suite. [Installed journal verification][installed] · [Co-design plan](codesign.md#landing)
The RTDB [Multi runner][runner] records the TLC baseline and targeted mutations.

The Logkeeper [study ledger](evidence.md) indexes individual results. The [independence audit](mechanism-independence.md) identifies the controls rerun for this workstream.
